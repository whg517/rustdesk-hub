# RustDesk Hub 首版整改与验收计划

按 [首版需求](requirements.md) 和 [技术设计](design.md) 推进。先在隔离 SQLite 实例重现问题，完成代码修复和自动化验收，再复审实现并处理新发现的问题。原生客户端验收使用两台实际运行 RustDesk 1.5.3 的设备。

| 顺序 | 实施项 | 验收条件 |
| --- | --- | --- |
| 1 | 设备 ID 规范化和旧数据处理 | 带空格 ID 与无空格 ID 共用同一条记录，前导零保留。按两种格式都能搜索、编辑和移除。旧数据升级保留条目关系，冲突时保留原记录并返回可定位的错误。 |
| 2 | 标签保留名与并发保存 | 两种入口都拒绝新增或改名为 `Untagged`。网页只改名时保留原生端已提交的新颜色。只改颜色时按稳定 ID 定位原标签，即使旧名已由别的标签复用。旧网页按名称写入时收到刷新提示。 |
| 3 | HTTPS 接入和可用性 | 拒绝默认客户端无法可靠使用的 HTTPS 21114 地址。验证直接 TLS、回环预览和反向代理配置。可执行文件在独立目录中提供管理页。缺失或不一致的内嵌资源在启动时报错。浏览器和服务端对 IPv6、国际化域名及默认端口的 Origin 识别一致。 |
| 4 | 网页故障恢复与诊断 | 浏览器遇到旧版页面资源加载失败时可以重新加载。接入页说明四个同步字段和客户端凭据管理。最近请求按请求 ID 查找。固定长度及流式超限、网页会话恢复和认证错误原因均有记录。 |
| 5 | 自动化验收与复审 | 同一测试库完成双向通讯录维护、并发、会话失效、重启和数据恢复。复审升级路径及需求覆盖，修复新增发现后重跑受影响场景。 |
| 6 | 双端实机验收 | Mac 和 Windows 使用双方都信任的 HTTPS 地址，实测登录、会话恢复、双向刷新和从同步条目发起连接。另测不受信证书、离线退出和本机忘记远控密码。 |
