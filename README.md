# RustDesk Hub

RustDesk Hub 面向自建 RustDesk Server OSS。多位用户可以各自登录网页和原生 RustDesk 客户端，同步自己的个人通讯录。管理员在网页中维护用户和查看请求诊断。

首版功能、数据规则和验收场景见 [首版需求](docs/requirements.md)。[技术设计](docs/design.md)记录 RustDesk 1.5.3 的兼容接口、数据规则和联调步骤。[整改与验收计划](docs/implementation-plan.md)记录实施顺序和验收进度。

## 构建与运行

准备 Go 1.27.4、可用的 C 编译器、Node.js 和 pnpm。先构建管理端，再编译 Hub。Go 将网页产物嵌入可执行文件。

```sh
pnpm -C web install --frozen-lockfile
pnpm -C web build
go build -o rustdesk-hub ./cmd/rustdesk-hub
./rustdesk-hub init-owner owner
./rustdesk-hub
```

初始化命令会提示输入至少 12 个字符的密码。打开 [本机管理端](http://127.0.0.1:8080) 后可用管理员账号登录。默认数据库为 `data/hub.sqlite3`，可在子命令前指定 `-db` 选用其他文件。运行 `go test ./...` 验证原生 HTTP 契约、网页读写、账号隔离和 SQLite 持久化。

部署时复制 `rustdesk-hub` 可执行文件，并为实例提供配置、SQLite 数据目录以及直接提供 HTTPS 时所需的证书文件。若启动提示内嵌管理端资源不可用，请先完成网页构建，再重新编译 Hub。

使用容器部署、配置 Quay 凭据或发布版本时，见 [流水线与容器发布](docs/ci-and-release.md)。

## 运行配置

从项目根目录复制 [配置示例](config.example.yaml)，再按部署环境编辑。

```sh
cp config.example.yaml config.yaml
```

启动服务和执行 `init-owner` 时都会读取工作目录中的 `config.yaml`。缺少默认文件时使用内置值。用 `-config /path/to/config.yaml` 指定其他文件，参数写在子命令前。设置按内置默认值、文件、显式命令行参数的顺序覆盖。相对文件路径以 Hub 的启动目录为准，修改后重启生效。

从外置网页目录的版本升级时，从配置文件和启动命令中删除旧的 `web-dir` 设置。旧配置文件中的这项会被忽略。

## 管理用户

管理员登录后，进入「用户管理 → 新建用户」，填写账号名和初始密码。用户可以用这组凭据登录网页和 RustDesk 1.5.3，在各端同步自己的个人通讯录。账号名区分大小写，密码规则与管理员一致。

管理员可以停用、启用和重置普通账号的密码。停用或重置密码会使该账号现有的网页及原生会话失效，启用后可重新登录并访问原有通讯录。用户在「账号设置」修改自己的密码。

## 系统设置

管理员在网页「系统设置」填写客户端可访问的 ID 服务器、可选的中继服务器，以及 RustDesk Server OSS 的 `id_ed25519.pub` 公钥。API 服务器地址由 Hub 的 `public-url` 生成。

保存即生效。重新进入客户端接入页可复制新配置，刷新通讯录可取得新的连接链接和在线查询结果。客户端需要采用新参数时，重新导入配置。

## 接入 RustDesk

部署时在 `config.yaml` 的 `public-url` 配置浏览器和两台客户端可访问并信任的 HTTPS 地址，例如 `https://hub.example.com`。优先使用 443。RustDesk 1.5.3 默认会移除 HTTPS 地址中的显式端口 21114，Hub 启动时会拒绝这种配置。

- 同机反向代理可转发到默认的 `127.0.0.1:8080`，保留请求方法、Authorization 头和请求体。跨主机代理设置 `behind-proxy: true`，并将上游监听限制为代理可达。紧邻 Hub 的代理可覆盖 `X-Forwarded-For`，或将它收到的连接来源追加到末尾，供 Hub 按来源限制登录尝试。
- 直接提供 HTTPS 时，填写 `tls-cert`、`tls-key` 对应的文件路径和所需的 `listen` 地址。

登录 Hub，在「客户端接入」（管理员入口为「接入与诊断」）复制 API 服务器地址。打开 RustDesk 1.5.3 的「设置 → 网络 → ID/中继服务器」（ID/Relay server），在弹窗的「API 服务器」填入地址并保存。随后在客户端的「账号」页登录并打开「个人通讯录」。ID 服务器、中继服务器和公钥填写自建 RustDesk Server OSS 的配置。

### 复制完整配置与发起连接

管理员在「系统设置」保存 ID 服务器和公钥后，用户可取得完整配置或发起连接。

- 在客户端接入页点击「复制 RustDesk 配置」。在 RustDesk 的「ID/中继服务器」弹窗点「导入服务器配置」，确认并登录。
- 「个人通讯录 → 连接」在浏览器中打开本机 RustDesk，按被控端设置完成授权。浏览器无法打开时，从该行的「更多操作」复制连接地址，再粘贴到 RustDesk 的目标输入框。使用 IPv6 ID 服务器时直接提供复制连接地址。

本机 HTTP 预览的 API 地址从当前主机可访问。其他设备要同步通讯录时使用它们能访问并信任的 Hub HTTPS 地址。 [接入与连接设计](docs/client-setup-and-connect.md)

## 查看设备在线状态

在「系统设置」打开「启用在线查询」。查询默认使用上方的 ID 服务器。Hub 通过内网访问同一套 OSS 时，可单独填写「在线查询地址」。

可省略默认 ID 端口 `21116`。Hub 从自身所在的网络访问 **ID 端口减一**，即默认 TCP `21115`。如果 Hub 与 OSS 1.1.16 部署在同一台主机，使用 Hub 可达的非回环地址，例如宿主机局域网 IP 或 Docker 网络内的服务地址。1.1.16 将来自回环接口的连接交给本地控制台。 [OSS 端口定义](https://github.com/rustdesk/rustdesk-server/blob/1.1.16/src/rendezvous_server.rs#L94-L114) · [OSS 查询入口](https://github.com/rustdesk/rustdesk-server/blob/1.1.16/src/rendezvous_server.rs#L1094-L1134)

打开网页的「个人通讯录」即可查看当前页的在线状态和查询时间。长时间打开页面后，点击「刷新」重新查询。在线表示该设备近期在配置的 ID 服务器注册。ID 服务器未配置或无法查询时显示「未知」，仍可正常编辑和同步通讯录。

## 更新

按上面的顺序重新构建网页和可执行文件，再替换程序。Hub 在启动时校验嵌入的首页、构建清单和资源文件。部署后检查首页、静态资源及 `/healthz`。健康检查在初始化的 SQLite 库可用时返回 `200`。升级后旧标签页若提示页面加载失败，点击「重新加载」即可获取新版本。

升级前使用 SQLite 备份方式保存数据库，并正常停止旧实例。升级会统一旧设备 ID 的分隔空格。若日志指出有重复 ID，在升级前的版本中核对两条记录的别名、标签和备注，保留所需数据后再升级。

从单账号版本升级时，现有账号会成为初始管理员，原有通讯录及未过期会话可继续使用。升级后由该账号在网页中添加用户。

从文件配置版本升级时，首次启动将旧的 `rustdesk` 和 `hbbs` 值导入 SQLite。客户端参数和在线查询地址各自校验，校验失败的部分可在网页重新填写。确认「系统设置」显示预期地址后，可以从部署配置中移除旧字段。以后通过网页保存，启动时加载数据库中的设置。
