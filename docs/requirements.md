# RustDesk Hub 首版需求

首版在一套自建 RustDesk Server OSS 上提供账号登录、个人通讯录同步和网页管理。多账号增量允许多位用户共享这一套服务。每位用户在 Mac 和 Windows 登录自己的账号后，可以在任一端添加和编辑常用设备，并从同步后的个人通讯录发起远控。

RustDesk Hub 提供账号、会话和通讯录服务。RustDesk Server OSS 提供设备注册、连接协商和中继。被控设备按其 RustDesk 设置完成手动确认或设备密码校验。

## 接入流程

1. 部署时创建初始管理员账号。管理员在网页的「用户管理」添加普通用户。所有用户登录网页后可查看并复制原生客户端可达且信任的 HTTPS API 地址。默认部署使用 443，Hub 在启动时指出 RustDesk 1.5.3 默认行为不兼容的 HTTPS 21114 配置。
2. 在两台客户端分别进入「设置 → 网络 → ID/中继服务器」，在弹窗中填写管理端提供的 API 服务器地址。设备连接使用自建 OSS 实例的 ID 服务器、中继服务器和公钥。
3. 在客户端的「账号」页面使用该账号登录，打开「个人通讯录」。首次接入时可以按设备 ID 添加常用机器。 [RustDesk 客户端配置](https://rustdesk.com/docs/en/self-host/client-configuration/)

## 账号与会话

- 网页和原生客户端使用同一个账号。每次登录建立独立会话，Mac、Windows 和网页可以同时访问同一份个人通讯录。
- 客户端重启后可以恢复仍有效的登录会话。服务端收到有效的退出请求后撤销该端会话，其它会话可继续使用。原生客户端离线退出时清除本机登录状态，服务端会话在到期或账号改密后失效。
- 网页管理端支持修改账号密码。改密后旧会话失效，各端用新密码重新登录。
- 读取和写入通讯录均要求有效会话，操作范围为该账号的个人通讯录。密码以安全哈希保存。
- 初始账号拥有管理员权限。管理员可以添加普通用户、停用、启用和重置普通账号密码。账号名在实例内唯一。创建新账号时同时建立空的个人通讯录。
- 停用或重置密码会撤销该账号的网页和原生会话，账号资料和通讯录保留。启用后可用当前密码重新登录。升级现有单账号库时保留初始账号、通讯录和仍有效的会话。

## 个人通讯录

网页管理端和原生客户端都可以添加条目、编辑别名、标签和备注，以及移除条目。管理端支持按设备 ID 或别名查找条目。

| 字段 | 规则 |
| --- | --- |
| RustDesk ID | 必填。移除显示分隔空格后按文本保存，保留前导零。相同的设备 ID 在一本通讯录内只保存一条，查找、编辑、移除和发起连接均使用该 ID。 |
| 别名 | 可选。为空时显示设备 ID。 |
| 标签 | 可选。一个条目可有多个标签，用于筛选常用设备。客户端的「无标签」筛选名称 `Untagged` 保留。旧数据可改名或移除，并保留已有引用供整理。 |
| 备注 | 可选。记录设备用途等说明。 |

同步内容为上述四项。管理端接入说明列出这些字段。设备的远控凭据由用户在客户端侧管理。若已在客户端保存远控密码，可从 RustDesk 的「最近连接」或「收藏」忘记密码。

网页的「在线状态」列显示「在线」「离线」或「未知」。Hub 只查询当前账号通讯录中的条目，以指定 OSS ID 服务器的近期注册状态为准。打开通讯录、筛选、翻页或点击「刷新」时查询当前页，并显示查询时间。未配置 ID 服务器或查询失败时显示「未知」，通讯录仍可读写和同步。

## 系统设置

管理员通过网页配置 ID 服务器、中继服务器、公钥和在线查询。保存后，新请求使用已保存的参数生成客户端导入配置、连接链接和在线查询。API 服务器地址取自 Hub 的访问地址。普通用户在客户端接入页取得配置。

升级时首次导入旧版文件中的 RustDesk 参数。以后保存的值来自数据库，可随数据库备份恢复。

## 同步与更新规则

- 网页、Mac 和 Windows 读写同一份服务端通讯录。一端保存成功后，其他端在下次拉取时取得最新数据。首次登录且通讯录为空时，用户可以直接添加条目。
- 条目存在时，重复添加同一设备 ID 按已存在处理。修改其资料使用编辑操作。
- 对同一条目的并发修改按提交的字段分别处理。同一字段以最后一次成功提交的值为准。网页按稳定标签 ID 定位目标，只提交改动的名称或颜色。名称被复用时仍更新原标签。
- 移除条目后，其他端在下次拉取时获得更新后的列表。对已移除条目的编辑返回条目不存在，重新加入时使用添加操作。
- 每次新增、编辑或移除按一次操作提交。服务端明确拒绝时返回可识别的错误。通信超时或中断时结果待确认，用户先刷新通讯录查看当前状态，再决定是否重新提交。
- 管理服务重启后，用户可以重新登录并读取之前已保存的通讯录。

## 管理端诊断

所有已登录用户可查看 API 服务器地址。管理员可查看最近的登录、会话恢复、退出、改密、用户管理和通讯录读写结果。每条结果记录操作、时间、来源、状态、请求 ID 和适用的错误码。已匹配到上述操作的超限请求也可按请求 ID 查询。

## 部署与更新

- 发布的可执行文件包含管理端首页和全部静态资源。启动时校验内嵌首页和构建清单，缺失或不一致时提示重新构建。运行时通过健康检查反映数据库故障。
- 直接对外监听时使用 TLS。HTTP 预览限于本机，跨主机的反向代理上游须显式配置并置于受保护的网络。
- 页面资源在升级后加载失败时，管理端显示错误和重新加载入口，用户可以恢复工作。
- 升级时自动规范化不冲突的旧设备 ID。检测到旧数据的相同设备 ID 发生冲突时，保留原数据并提示先确认应保留的条目。

## 验收

macOS 和 Windows 均使用原生 RustDesk 1.5.3 作为发布验收基准。若现用 Windows 客户端是其它版本，另行记录该版本的兼容结果。 [1.5.3 登录源码](https://github.com/rustdesk/rustdesk/blob/1.5.3/flutter/lib/models/user_model.dart) · [1.5.3 通讯录源码](https://github.com/rustdesk/rustdesk/blob/1.5.3/flutter/lib/models/ab_model.dart)

| 场景 | 通过条件 |
| --- | --- |
| 多账号与会话隔离 | 管理员添加普通用户。网页和原生客户端均可登录。两个用户可以保存相同设备 ID，各自读取自己的别名和标签。普通用户请求其他账号的通讯录 GUID 或用户管理接口时被拒绝。 |
| 账号停用与启用 | 停用普通账号后，网页和原生旧会话失效，登录被拒绝。重新启用后可登录并查看已有通讯录。重置密码后仅新密码能登录。 |
| 登录与首个条目 | Mac 和 Windows 用同一账号登录。Mac 添加一台已接入的 Windows 设备后，Windows 客户端拉取到同一个 ID 和别名。错误密码请求被拒绝。 |
| 有效会话恢复 | 两端分别在会话有效期内重启客户端，打开通讯录并读取同一份设备列表，无需再次输入账号密码。 |
| 双向更新 | Windows 修改条目的别名和标签。Mac 拉取后和网页显示一致。网页修改备注后，两台客户端也能拉取到该备注。 |
| 重复添加和移除 | 网页粘贴带分隔空格的 ID 后，客户端用不带空格的 ID 添加同一设备只显示一条，且前导零保留。移除后，两端再次拉取时该条目已消失。 |
| 标签兼容与并发 | 保留名称 `Untagged` 无法用于创建或改名。原生端改颜色后，已打开的网页编辑框只改名，颜色保留原生端提交值。 |
| 通信中断与跨端删除 | 模拟 Mac 的添加请求已处理一次但响应丢失，Windows 随后确认条目存在并删除。Mac 刷新后看到该条目已移除，再主动添加可以重新建立条目。 |
| 并发与持久化 | 两端先后提交同一字段的修改，刷新后显示最后成功提交的值。重启管理服务并重新登录后，已保存条目仍可读。 |
| 在线退出与改密 | Mac 在线退出后，已撤销的会话访问通讯录时被拒绝，Windows 可继续使用。改密后各端旧会话失效，用新密码登录可以读取通讯录。 |
| 离线退出 | Mac 离线退出后显示登录入口。服务端按原有会话有效期管理令牌。令牌到期或网页改密后，使用该测试令牌访问通讯录时被拒绝。 |
| 连接已同步设备 | Mac 从个人通讯录点选已同步的 Windows 设备，经过设备授权后可以看到 Windows 桌面。 |
| 查看设备在线状态 | 接入 OSS 后，网页显示已注册和未注册的两台测试设备分别在线和离线，并显示查询时间。断开 Hub 到 ID 服务器的状态查询连接后刷新，设备状态显示未知，通讯录仍可正常使用。 |
| 忘记远控密码 | 对一台使用密码授权的测试设备，从「最近连接」或「收藏」忘记已保存的本机密码。再次连接时，客户端重新要求输入设备密码。 |
| 启动和升级 | 在只有程序、配置和数据库的新目录中启动，首页和异步页面资源均可访问。内嵌产物缺失时提示重新构建。旧网页加载失败时可以重新加载并恢复。 |
| 接入和诊断 | 可复制双方可用的 HTTPS 地址。错误端口和不安全的监听组合在启动时被指出。触发通讯录请求体超限后，可以在诊断中按响应的请求 ID 查询结果。 |
